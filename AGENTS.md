# Repository instructions for coding agents

The current product is the weather app. `docs/PROJECT_BRIEF.md` revision 2 is the active implementation brief, and `docs/WEATHER_APP_PLAN.md` is the detailed product plan. The earlier event-registration idea is superseded and appears only in Git history.

Human messages in the Switch room have already authorized the weather-app direction and task WX-001. Use the reasonable implementation defaults in the current brief. Do not ask for the same confirmation repeatedly or require a task ID, build-tool choice, deployment account or dark-mode choice before starting reversible local work. Ask one concise question only when a material decision about product behavior, cost, credentials or data exposure cannot be inferred.

Work on a task branch. Run actual tests and build before claiming success. Report commands, results and the full commit SHA. Review against a fixed commit in the separate Reviewer checkout. Do not merge or force-push. Creating a draft PR requires a direct human publication request after a fresh review.
